# 3. Conflict Plan

## 3.1 Resolving Disagreements

When disagreements arise:

1. Clearly explain the issue.
2. Each teammate shares their perspective.
3. Discuss technical pros and cons.
4. Reach consensus whenever possible.
5. If consensus isn't possible, choose the solution supported by the majority while respecting everyone's opinions.

---

## 3.2 If Someone Is Dominating

First:
- Speak privately and respectfully.

Escalation:
- Discuss as a team.
- If unresolved, involve the Support Instructor.

---

## 3.3 If Someone Is Under-Contributing

First:
- Reach out privately to understand the situation.

Escalation:
- Redistribute work if necessary.
- Contact the Support Instructor if the issue continues.

---

## 3.4 Handling Different Skill Levels

Experienced teammates will mentor without taking over implementation.

Less experienced teammates are encouraged to ask questions early and pair-program whenever needed.

# 5. Work Plan

## 5.1 Task Management

The project will be divided into features and milestones.

Each feature becomes one or more GitHub Project tasks.

Every task has:
- Owner (Assignee)
- Due date
- Status

A task is complete only after:

- Pull Request approved
- Tests pass
- PR merged into main
- Demonstrated during team sync

---

## 5.2 Anti-Siloing

We agree that:

- Every PR receives at least two reviews.
- Everyone pair-programs at least once outside their primary specialty.
- Every teammate understands the full project.

---

## 5.3 No Solo Committing

We agree not to make major unplanned commits directly to the shared project without team awareness.

Experimental work should remain on personal branches until reviewed.

## 6.2 Branch Strategy

- `main` → production-ready
- `main` → integration branch
- Feature branches:

```
feature/<feature-name>
```

One feature per branch.

Delete merged branches.

---

## 6.3 Pull Request Workflow

Every PR requires:

- 2 approvals
- Passing tests
- Meaningful description
- Linked GitHub Project task

PR titles:

```
feature/authentication: implement JWT login
```

PR body includes:

- Summary
- Testing evidence
- Reviewer notes

---

## 6.4 Merge Cadence

Feature branches merge into `main` throughout the day, after successful integration testing.

Ready PRs are announced in the team chat.
